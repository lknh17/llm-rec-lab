# 第 1 步 / 共 15 步：场景与痛点

> 阶段 1 / 6：**理解任务**

内容理解打标要在 **7B** 上做 SFT。直接全参微调：AdamW 混合精度约 16 字节/参数，7B 要约 122 GB 显存，一张 96 GB 的 H20 放不下，还要为每个业务存一份 15 GB 的完整权重。

LoRA 把要训练的东西缩小到原来的 0.1%-1%，但带来三个必须回答的问题：

1. **rank 配多大、挂在哪些层**：可训练参数差几十倍，效果差多少？
2. **监督哪些 token**：系统提示和广告原文要不要算 loss？
3. **数据侧故障**：训练"正常结束"但什么都没学到，怎么在上线前发现？

本课的任务是**广告元素抽取**：从广告文案里抽出品类、卖点、优惠及其适用条件，输出 JSON；原文没写的必须为空，不能编造。

| 输入 | 期望输出 |
| - | - |
| 跑鞋轻量透气，第二件半价，指定款参加 | `{"category":"跑鞋","selling_points":["轻量","透气"],"promotions":[{"offer":"第二件半价","condition":"指定款"}]}` |

难点在条件：必须保留"指定款"，不能写成所有跑鞋都半价。

| 集合 | 条数 | 来源 |
| - | - | - |
| 训练集 | 4000（H20）/ 400（Mac 历史） | 模板生成的教学合成数据（[`synth.py`](../../../projects/adextract/synth.py)），16 个品类、虚构品牌 |
| dev | 30 | 人工撰写并逐条核对（[`evalsets/`](../../../projects/adextract/evalsets/)） |
| 合成验证集 | 60 | 同一生成器、不同种子 |
| test | 30 | 人工撰写，保留到最终检验 |

**指标**（规则评测，见 `schema.py` 的 `score_one`）：**全对率**（所有字段都对，本课主指标）、格式合法率、品类准确率、卖点 F1、优惠召回、条件保留率、无依据率（编造）。

**怎么读噪声**：dev 只有 30 条，**一条样本 = 3.3 个百分点**；H20 档每个场景 3 个种子。小于 3.3 个点、或小于种子间波动的差异都当噪声处理。

**本课的读法**：后面每一步先读问题、自己选一个答案，再展开"实测"。实测都是 H20 上预先跑好的结果（作业进度见 [jobs/](../../../jobs/README.md)）。
